# Interview notes — repository conventions

**No interview has been conducted.** This directory contains templates only. Do
not add a file here that implies a conversation happened unless one did.

## File naming

`YYYY-MM-DD-<pseudonym>-<scenario>.md`, for example
`2026-10-20-p01-suspicious-transfer.md`.

## Rules

1. **No identifiers.** No name, phone, address, employer, card digits, account
   number, document data or precise location. Not in the filename, not in the
   body, not in a screenshot filename.
2. **Pseudonyms only.** `p01`, `p02`, … assigned in order of recruitment.
3. **Anonymised notes, not transcripts.** Summarise. A verbatim quote is fine
   only after removing anything identifying.
4. **Consent first.** No note file without a matching consent record stating what
   was agreed.
5. **Store only what the questions need.** `research/participants/data_minimization_notice.md`
   lists what is deliberately not collected.
6. **No client statements, no screenshots of real statements.** If a participant
   offers one, decline and note that you declined.

## Structure

Use `template_anonymized_notes.md`. Every note ends with:

- which of H1–H6 the episode speaks to;
- what would have changed the participant's mind;
- anything the guide failed to capture.

## When to stop and escalate

- the participant discloses an ongoing fraud attempt → stop the interview, note
  only that it was disclosed, and hand over to the security owner;
- the participant becomes distressed → stop;
- anything identifying is about to be written down → stop and remove it.

## Aggregation

Once notes exist, `docs/hypothesis_tracker.md` is the only place a conclusion may
be recorded, with the note ids that support it. A conclusion with no note ids is
not a finding.
