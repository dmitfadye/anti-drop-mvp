## Правила чтения

- **VERIFIED** — непосредственное чтение кода или выполненная проверка, в указанном объёме.
- **PARTIAL** — часть функции работает; результат целиком не подтверждён.
- **DOCUMENTED ONLY** — только обещание документации.
- **NOT VERIFIED / НЕ ПОДТВЕРЖДЕНО** — данных нет или проверка не проведена.
- **BROKEN** — безопасно воспроизведено нарушение ожидаемого контракта.

Отсутствие компонента означает отсутствие в исследованном дереве, а не доказательство отсутствия вне репозитория. Диапазоны ниже относятся к неизменённому коду, не к новым отчётам.

### Как повторить существенные проверки

Только синтетические данные; `TestClient(app, raise_server_exceptions=False)`.

```python
client.post('/api/analyze', json={'transactions': [{'ts': 'bad', 'amount': 1}]})
# Фактически 500, ожидается контролируемый 422.
client.post('/api/analyze', json={'transactions': [
    {'ts': '2026-10-07T14:00:00+03:00', 'amount': 1},
    {'ts': '2026-10-07 14:00:00', 'amount': 1}]})
# Фактически 500; нужна единая политика времени.
```

Для mixed_users: пять входящих по 3000 от разных контрагентов, каждый на отдельный user_id, и исходящий 14000 у шестого user_id, одно время 14:00. Общий RED/70 показывает смешение субъектов. Для SIM=0: две входящие операции с разными контрагентами и sim_changed_days_ago=0 дают metrics.sim_changed_recently=false.
