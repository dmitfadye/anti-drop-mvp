# MVP, пилот и дорожная карта

Дата **08.10.2026**. По кейсу: сдачи 01.11, 29.11, 08.12, финал 11.12. Все дедлайны ещё впереди. Текущий код не изменялся в аудите. Трудоёмкость — человеко-дни по 6 продуктивных часов, календарь зависит от доступности участников и банка.

## Один целевой сквозной сценарий

Пользователь с выбранным языком получает просьбу переслать поступившие деньги. В sandbox поступает доверенный синтетический эпизод одного клиента. Система валидирует данные, вычисляет версионный риск, показывает согласованный понятный текст и предлагает официальный путь помощи. Пользователь подтверждает обращение; сервер sandbox сохраняет кейс и возвращает устойчивый ID. Финал: клиент понимает дальнейшее безопасное действие, case подтверждён, событие включено в измерение. Доказанный эффект сейчас — выдача алерта; понимание/прекращение рискованного действия должны измеряться. Нельзя показать реальную блокировку, пока нет банковского enforcement.

**Важное ограничение текущего алгоритма:** пять небольших входящих днём без свежей SIM и без вывода дают 45/YELLOW, алерт появляется только при RED≥50. Нынешнее RED-демо включает уже совершённый вывод. Нельзя называть его предотвращением первого перевода. Для pre-transfer сценария нужен явно проектируемый draft event/сигнал банка и отдельная валидация; не выдавать будущую функцию за текущую.

## Приоритеты scope

| Класс | Функции |
|---|---|
| P0 конкурс | Один клиент/эпизод; корректные дата/SIM/amount/id; безопасный DOM; нейтральный согласованный первый язык + RU; offline assets; honest demo; case mock с подтверждённым state; метрики и исследование; reproducible run/tests |
| P1 если хватает времени | Второй приоритетный язык с носителями, отдельный экран оператора sandbox, расширение legitimate fixtures, простой CI/container, доступность/RTL для реально выбранного языка |
| P2 после доказательства | Bank OTP/recovery, изменение номера и enforcement; trained ML по размеченным данным; event scale/HA; новые каналы |
| REMOVE из главного питча | Cashback как доказанное начисление, автономная «заморозка», обещание поддержки за 2 минуты, отдельная SIM-фича, заявления «85% вероятность» и «лучше банковского антифрода» |

REMOVE — рекомендация о фокусе, не выполненное удаление файлов. Полностью рабочий SMS-flow не является обязательным для выбранного конкурса, если он не заявлен в MVP.

## Acceptance criteria и тесты

1. Один запуск на чистой согласованной среде; locked dependencies; демо без публичной сети. README-команда и поставляемый artifact совпадают.
2. Invalid/mixed-timezone/payload возвращают документированный 4xx; не 500. Mixed subject и duplicate IDs отклоняются или разделяются по явному контракту. SIM 0/1/2 корректны; будущие и нулевые операции не создают риск без правила.
3. Score/level/reason codes детерминированы с rule_version; score не выдаётся как вероятность. Исторический replay явно обозначен.
4. Норма, атака, legitimate high-activity, borderline и недоступный API показаны заранее; UI не оставляет ложный success и устаревший ответ после переключения.
5. Предупреждение говорит о риске, а не приговоре; первый целевой язык проверен носителем и юридическим review. Все действия главного пути локализованы.
6. Case mock сохраняет состояние: repeated idempotency key возвращает тот же case_id; ошибка/таймаут даёт unknown/failed и безопасный repeat. Банковская блокировка не симулируется как факт.
7. Нельзя читать/изменять кейс другого sandbox subject. Logs минимальны; реальные телефоны/операции не используются.
8. Primary metric и guardrails определены до эксперимента; baseline либо измерен, либо явно неизвестен. Два сценария не выданы за accuracy dataset.

Минимальные проверки: contract/negative из TECHNICAL_AUDIT; перезапуск с чтением сохранённого case; replay idempotency; unauthorized/cross-subject; UI error/slow request/offline; контроль approved template/version и отсутствие ответов квиза в публичном content. Синтетика должна включать добросовестные сборы, зарплату/наличные, ночных работников, повторы и границы окна, без имитации этнического risk scoring.

## Проектируемые контракты интеграций (не реализованы)

`RiskSnapshotV1`: subject_ref из trusted context; analysis_at ISO UTC; event_id/source, occurred_at, amount_minor, currency, direction/type, counterparty_ref, trusted device/SIM flags; schema_version. Ограничения: один subject, уникальные source+event_id, bounded size и допустимые часы. `RiskDecisionV1`: evaluation_id, analysis_at, rule_version, level, score, reason_codes, template_id, status (`ok`/`insufficient_data`), без raw идентификаторов в тексте.

`POST /sandbox/cases`: evaluation_id, selected_language, contact_reason, Idempotency-Key; identity серверная. Ответ: case_id, status=`created`, created_at, next_step; HTTP 201 для нового, повтор → тот же ресурс. 4xx/5xx/timeout различаются; без выдуманной гарантии срока поддержки. `GET case/{id}` проверяет subject/роль. Mock интерфейса банка выдаёт только тестовые статусы; sandbox adapter никогда не сообщает payment_blocked без внешнего подтверждения. Эти имена контрактов — предложение отчёта, не существующие маршруты.

Демо без API банка: заранее описанный event source, sandbox case DB, искусственные роли, fixtures, видимый badge «синтетика/песочница». Записать offline видео как backup после исправлений; текущего видео в репозитории нет.

| 9–11 дек: репетиция/резерв | P0 финала | 1–2 д | Стабильный релиз | Видео backup, frozen demo, Q&A; никаких крупных миграций |

Оценки пересекаются по людям и требуют планирования, их нельзя сложить в календарь одного разработчика. До 1 ноября доступно около 3 недель; для двух участников полный список может не поместиться. **Сокращать scope:** оставить RU+один целевой язык, API+предупреждение+case, исключить SIM и reward, не мигрировать frontend. Продуктовый участник ведёт интервью/артефакты, инженер — исправления/case; QA выполняют взаимно. Если 3–5 человек, отдельно выделить исследование/аналитику и вторую инженерную/QA роль; ИБ/юриста/носителя привлекать на конкретные review. Наличие этих компетенций ещё не подтверждено.

## Предложение пилота ВТБ

Потенциальная функция: клиентская antifraud-безопасность совместно с розничным digital и поддержкой. Предполагаемый process owner — руководитель клиентского antifraud/цифровых предупреждений; конкретных сотрудников и согласия ВТБ нет.

1. **Feasibility:** 200–500 добровольных участников из согласованного сегмента, первый язык, 2–4 недели, сценарное понимание и доставка; без доказательства реального fraud ROI.
2. **Shadow:** разрешённая историческая/псевдонимизированная выборка и read-only поток, 4–6 недель как плановая гипотеза. Сравнить с текущим сигналом и обработкой банка, не менять платежи.
3. **UX A/B:** только после gate; одинаковая текущая защита в обеих группах, новый слой текста/помощи в treatment. Размер определяется power и event rate; может быть существенно больше feasibility, срок зависит от частоты событий.

Вход: владелец, данные/законные основания, reviewed templates, access controls, data contract, instrumented baseline, power plan, support capacity, security gate. Успех: положительный primary uplift с CI, guardrails в пределах noninferiority margin, допустимые false alerts/support cost и экономика на согласованном масштабе. Draft thresholds из PRODUCT_AND_MARKET обсуждаются с банком, не являются обещанием.

Остановка: любая подтверждённая cross-subject утечка/несанкционированное действие — немедленно; превышение согласованных ошибок/нагрузки, жалобы/вред от формулировок — приостановка и review; недостаточная мощность/нет эффекта — не объявлять успех. Rollback: выключить feature flag адаптированного слоя, вернуть стандартное банковское предупреждение; не отключать защиту банка. Масштабирование по языкам/каналам после отдельно подтверждённой понятности и capacity; HA/event scale только по замерам.

Блокеры внешнего происхождения: доступ к респондентам, разметке/агрегатам, owner/ИБ и sandbox-контракту. Они блокируют доказательство пилота, но не синтетическое конкурсное демо. Если времени мало: сначала честность и главные runtime-дефекты, затем реальные интервью и измерение понимания, затем case. Не тратить неделю на Next.js, Kubernetes или LLM.
