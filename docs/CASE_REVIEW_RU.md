Проверено 8 октября 2026. Репозиторий dmitfadye/anti-drop-mvp, commit 565c72017c1be04e0734998b435d9db508940de9.
Основание: текст кейса, предоставленный пользователем, исходный код и локальные проверки. Это техническая и продуктовая оценка, а не юридическое заключение; правовые утверждения из приложения не проверялись.

## Вывод

По тематике проект подходит: одновременно закрывает направления защиты от мошенничества и помощи нерезидентам. Это работающий демонстрационный прототип, хорошая основа для первого спринта, но не готовый банковский пилот и не полный комплект финальной заявки. Финальная оценка жюри по одному репозиторию невозможна.

## Что запущено и проверено

- Python 3.12, отдельное окружение .venv, зависимости из requirements.txt.
- FastAPI на http://127.0.0.1:8000; Swagger /docs. Доступ только с этого ПК. Автозапуск после перезагрузки не настроен.
- 14 из 14 штатных unittest-тестов прошли.
- Живой HTTP: /, /api/health, /docs, /openapi.json возвращают 200.
- CSV normal: GREEN, 0; CSV drop_attack: RED, 85, запрос алерта на узбекском языке.
- Проверка проведена на уровне кода и HTTP; визуальная проверка браузера не выполнялась.
- Повторный запуск: powershell -ExecutionPolicy Bypass -File .\start-local.ps1.
- PID текущего процесса: .local/server.pid; журналы: .local/server.out.log и .local/server.err.log.
- Исходный функциональный код не изменён. Добавлены этот отчёт и скрипт запуска.

## Что на самом деле демонстрируется

main.py принимает операции целиком через API; детектор использует правила и пороги, а не обученную модель. Поддержка в интерфейсе имитируется на клиенте. Квиз возвращает сообщение о кешбэке, но платежа и постоянного учёта нет. Смена номера принимает otp_ok_old/otp_ok_new от клиента: проверки SMS-кодов нет. Новый номер, кулдаун и лимиты лишь возвращаются в ответе; они не сохраняются и не применяются к платежам. Обучение и интерфейс преимущественно русскоязычные; семь языков относятся к алертам, а не полной локализации продукта.

## Технические проблемы

1. Подтверждено: ts='not-a-date' проходит Pydantic как строка и приводит к HTTP 500 вместо 422 (models.py, src/detector.py).
2. Подтверждено: смесь времени с часовым поясом и без него приводит к HTTP 500 при сортировке.
3. Подтверждено: sim_changed_days_ago=0 превращается в 999 выражением `value or 999`; смена SIM сегодня не распознаётся.
4. Анализ не группирует операции по user_id: смешанный пакет разных клиентов даёт общий риск. Нужно закрепить контракт одного клиента или группировать на сервере.
5. По умолчанию окно строится относительно последней операции, а не текущего времени. Это удобно для CSV-демо; для онлайн-защиты нужна явная семантика времени. При переданном now нет верхней границы для исключения будущих событий.
6. Ночная активность объявляется «нетипичной для вас» без персональной истории. Пороги не откалиброваны; возможны ложные тревоги на законных переводах и снятии зарплаты.
7. Причины вставляются через innerHTML; часть текста может включать device_id из API. При подключении недоверенного потока нужно безопасное отображение через textContent.
8. Зависимости requirements.txt имеют только нижние границы; воспроизводимую установку нужно закрепить. В репозитории есть uv.lock, но текущий README использует pip requirements.txt.
9. Файл лицензии не найден: публичность GitHub сама по себе не устанавливает условия повторного использования кода.
10. Категоричные юридические формулировки и переводы требуют проверки профильным специалистом; скоринг не доказывает преступление.
